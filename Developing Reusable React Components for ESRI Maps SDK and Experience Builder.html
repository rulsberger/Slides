Reusable React Components

for ESRI Maps SDK & Experience Builder

Presented by Ryan Ulsberger

Introduction

Experience Builder Development

Thanks for joining today’s discussion! Our work with Experience Builder has been effective, and now we’re looking at ways to build on that success:

  • Widgets are well-integrated into applications.
  • By making them more flexible, we can use them across projects.
  • A reusable approach helps us streamline development.

Looking Ahead

While Experience Builder remains a great tool, we see opportunities to prepare for:

  • ESRI Maps SDK standalone development.
  • Avoiding unnecessary rework by future-proofing our work.
  • Building components that seamlessly transition into future projects.

Proposed Solution

What if we proactively:

  • Develop reusable React components that work in both Experience Builder and standalone apps?
  • Reduce duplicate development while maintaining flexibility.
  • Standardize UI & logic across projects.

Proof of Concept

Introducing the IdentifyAll Widget:

  • Demonstrates decoupled development that enhances flexibility.
  • Functions in both Experience Builder and standalone ESRI Maps SDK apps.
  • Encapsulates core functionality into reusable React components.

Why Reusable React Components?

Key benefits:

  1. Reduce duplicate development
  2. Ensure smooth future transitions

💡 Preparing for the Transition to Web Development

We know Experience Builder isn’t our long-term solution...

  • ✅ Most of our UI logic will already be built—just connect it to a new framework.
  • ✅ No need to start from scratch, saving time and effort.
  • ✅ We can transition gradually, instead of all at once.

    • Addressing Concerns

    Is React a viable long-term solution?

    • ✅ ESRI actively supports React, ensuring compatibility.
    • ✅ React components can integrate into various frameworks.
    • ✅ React provides a stable and widely adopted API.

    Live Demo
